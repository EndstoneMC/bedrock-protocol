# Hand-written C++

- Include the repo's own headers with quotes and the full path from the include root (`"bedrock/protocol/stream.hpp"`); use `<>` only for the standard library and third-party headers; never use `./` or `../`.
- Name a header with its own `.cpp` `.h` and a header-only one `.hpp`; this holds for the generated headers too.
- Emit each schema module as a `.h` and a `.cpp` in the static library; never make generated code header-only.
- Give every version whose members match one C++ type, written out whole; give each distinct encoding of it one `Serializer<T, N>`, named for the first protocol N that uses it, which every other version's `Serializer<T, V>` inherits empty; never derive one version's type from another's.
- Where one protocol sends both encodings of a class name and they hold different members, name the hand-written form's type `<Name>` and the cereal form's `Cerealized<Name>` at those protocols only; `Cerealized<Name>_<V>` resolves nowhere else.
- Name a serialization mode only where a class name has two at a protocol: `Serializer<T, V, SerializationMode::Cereal>` or `SerializationMode::Manual`; `SerializationMode::Default` exists only where it has one, and a generated body calls a child by its implementation's first protocol and mode.
- Declare the type live at the latest protocol at the root of `bedrock::protocol` and every other under `v<N>`, N the first protocol that holds it and the first modelled protocol for the oldest; `X_<V>` selects the type of protocol V.
- Make every enum one `enum class` holding every member any protocol has, each member valued by its library value, its number at the newest protocol that has it; the generated codec maps it to each protocol's numbers and names.
- Open every header with `#pragma once`, with nothing above it.
- Keep one code path for every platform, toolchain and version: no `#if` alternative and no polyfill; raise the toolchain floor instead.
- Keep one namespace block per file with inner namespaces nested inside it; never close a namespace and reopen it.
- Use `struct` only for passive data with no invariant; anything with an invariant is a `class` with private members.
- Declare public, then protected, then private; within each, declare types, constants, constructors, methods, then data members.
- Mark a single-argument constructor `explicit`, except a sum type's constructors from its own alternatives.
- Return results as values (`std::expected`, or a struct to destructure); never write through an out-parameter.
- Say `serialize` and `deserialize` only on `Serializer<T, V>`; the entry points around it are the function objects `encode<V>(value[, writer])` and `decode<V, T>(data | reader)`; every call names its protocol.
- Give each protocol N a `v<N>` namespace holding only `version`, and `encode` and `decode<T>` bound to `encode<N>` and `decode<N, T>`.
- Pass a serialization mode as a trailing `cereal` or `manual` tag, only where a class name has two at that protocol.
- `Protocol` holds a modelled number from `protocol(number)` or `protocol(release)`, which resolve through `releases`, and reports a type its protocol lacks as `Errc::unknown_type`.
- Report bad encoded bytes, and a value its encoding cannot write, as `std::unexpected(Errc)`; generated code names the failing field with `stream.fail` on the reader and the writer; never throw for either.
- Check a value on encode only where its encoding is narrower than its member, failing one whose cast back differs with `Errc::out_of_range`.
- Decode a number a protocol gives a member to that member and any other number to a non-member value; reject a number the protocol cannot place, a name it lacks, a value it cannot number or name on encode, and text a text-coded `UUID` cannot parse, with `Errc::unknown_value`.
- Keep the per-protocol number and name tables in `detail`; the library exposes no per-protocol enum API.
- Spell the return type of every function in a public header; deduce one only where it cannot be named.
- Give every overload of a name one meaning; a length-prefixed write and a raw write take different names.
- Use `std::` fixed-width integers at the width the encoding declares, and `std::size_t` for counts and indices.
- Capture explicitly in a lambda that outlives its scope; use `[&]` only in one that runs in place.
- Constrain templates with concepts, branch with `if constexpr` and expand packs with fold expressions; never use SFINAE, `enable_if` or recursive instantiation.
- Own an object by value, or through `std::unique_ptr` when it must live on the heap; never use an owning `new`.
- Build strings with `std::format`, never with `+` chains of `std::string` and `std::to_string`.
- Name a std-shaped facility the std way (`packet_of_t`, `has_packet_v`, `enum_cast`); a hand-written type that mirrors a BDS type keeps BDS's names.
- Name a bound Python attribute in caps when it holds one value (`ID`) and in lower case when it holds a collection (`versions`, `packets`).
- Give a caster's name and a bound signature the type its stub must read: the module path (`bedrock_protocol.nbt.CompoundTag`), a generic's arguments, `object` for `__eq__`.
- Never run clang-format or clang-tidy on generated code.
