# Tests

## Goldens

- Generate a golden with BDS through bedrock-dumper wherever it can write the packet, and with Sandertv/gophertunnel otherwise (the `generating-goldens` skill); never derive bytes by hand.
- A BDS golden is the packet's default write, the one its own `SerializationMode` picks; compare it with the other writer.
- Paste a golden as a `bytes.fromhex(...)` literal directly under the comment `# generated by gophertunnel <commit>:` followed by the Go packet literal that produced it, or `# generated by BDS <build> (bedrock-dumper <commit>):` followed by the packet and its field values; that comment is the whole annotation, so never label the bytes field by field.
- Make an older era's golden with gophertunnel checked out at that era's commit, and give a cerealisation two goldens, one per era; never fake one by deleting bytes from a newer golden.
- Where gophertunnel cannot marshal the target shape, assert it structurally against the previous era's body: the size delta plus a round-trip of the new field.
- Pin a new field a second way: two bodies that differ only in it must differ only in its bytes.
- Never assert a reorder by size; pin the order with a body whose bytes move.
- Patch a golden without a TODO only to fold case; patch any other disagreement provisionally:
  - patch the bytes so the suite says what the schema encodes, and mark them `# TODO: patched, confirm against BDS`;
  - open the golden's comment with `# TODO: confirm against BDS`, naming what the reference wrote, what the dump says and which side has to give;
  - settle it per `.claude/rules/protocol/sources.md`.
- Check every golden both ways: encoding the packet yields the bytes, and decoding the bytes yields the packet.
- Write expected bytes only as literals; never compute them by re-implementing varints, zigzag, header packing or the codec.

## Writing a test

- Name a test for the behaviour it proves, as a lower-case sentence (`test_decode_rejects_trailing_bytes`), never for the function it calls.
- Prove one behaviour per test; a name that needs `and` is two tests.
- Put no loop, `if` or `try` in a test body: parametrize the cases with readable ids, assert a failure with `pytest.raises(..., match=...)`, and mark a known gap with `pytest.mark.xfail(strict=True)`.
- Reach the code only through the public `bedrock_protocol` package, never through a `_`-prefixed name; a missing public name is a gap in the binding.
- Pin a version-specific test by importing that version's module by name, never by position.
- Run version-independent behaviour over every bound version through one parametrized fixture.
- Share through fixtures, never `from conftest import`; a fixture never hides a value an assertion depends on.
- Use no mocks, monkeypatching or other doubles; drive the real extension with real values.
- Before trusting a new test, break the schema or the golden once and watch the test fail.

## Files

- Add a case to the test that owns its packet or topic; never open a second file for it.
- Per-packet goldens live in `test_{id:03}_{name}.py` (`test_009_text.py`); topics live in `test_<topic>.py`.
- Give a type that no modelled packet reaches its own test, named for the type.

## A red suite

- After a snapshot materializes, re-check every test that builds one era's types against another era's golden.
- Before blaming your change for a red suite, run the suite at HEAD in a clean worktree.
